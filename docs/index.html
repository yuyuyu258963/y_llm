01 / LEARN BY BUILDING

你不是在“调用模型”，
而是在拆解一个推理服务。

每个概念都落在一段尽量小的代码上：先观察数据在哪个设备，再建立单请求的正确性基线，最后才让请求并发、让 cache 被复用、让模型通过 HTTP 服务运行。

02 / THE DATA PATH

CPU 决定“做什么”，GPU 持有“算什么”。

把跨设备边界压缩到 token ID，是理解推理延迟的第一把钥匙。

CPU
HTTP / tokenizer解析请求，构造 token IDs
Request / Scheduler管理状态、队列与 execution plan
H2D · token IDs + metadata D2H · sampled token ID only
GPU
ModelRunner执行 prefill / decode，GPU argmax
Model + KV cacheToyAttentionLM / Qwen 与 K/V 状态

03 / INCREMENTAL PATH

先证明，再扩展。
每一层只多解决一个问题。

这不是把“最终代码”倒序讲一遍。新能力以 adapter 或新模块出现，前一章的 public API 与测试被视为冻结，避免未来的复杂性倒灌回基础概念。

    先看见设备边界

  2. 01–02

04 / EVIDENCE, NOT GUESSWORK

“更快”之前，
先回答“仍然正确吗？”

每条优化路径都保留参考实现。toy path 比较 full recompute 与 cached decode；真实模型 path 比较 native cache、完整前向和 Transformers generate。资源层还要证明 slot 与 block 不泄漏。
